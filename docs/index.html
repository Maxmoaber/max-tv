🎬 Max.tv

Plataforma web de streaming de películas y series — Documentación del proyecto

React Vite Tailwind CSS Node.js Express Prisma ORM PostgreSQL TMDb API

1. Descripción General

Max.tv es una aplicación web que permite explorar películas y series en tendencia, buscar contenido, guardar favoritos y ver tráilers. Consume la API de The Movie Database (TMDb) para obtener contenido real y utiliza un backend propio para la gestión de usuarios y favoritos.

Objetivo académico: El proyecto demuestra el uso de tecnologías web modernas: frontend React con Vite, backend Node.js/Express, base de datos PostgreSQL (Neon), autenticación JWT y consumo de APIs externas.

2. Arquitectura del Sistema

El proyecto sigue una arquitectura cliente-servidor con dos componentes principales:

  • Frontend (React + Vite): Interfaz de usuario, alojado en Netlify.
  • Backend (Node.js + Express): API REST, alojado en Render/Railway.
  • Base de datos (PostgreSQL): Almacenamiento en Neon.
  • API externa TMDb: Fuente de datos de películas y series.

3. Casos de Uso

3.1 Explorar contenido en tendencia

Actores: Usuario (autenticado o no)

Flujo:

  1. El usuario ingresa a la página principal (/).
  2. El frontend solicita GET /api/tmdb/trending al backend.
  3. El backend consulta TMDb y devuelve las tendencias de la semana.
  4. Se muestran en el Hero (banner principal) y en el carrusel "Tendencias".
  5. El usuario puede navegar los carruseles con los botones izquierda/derecha.

3.2 Buscar películas y series

Actores: Usuario (autenticado o no)

Flujo:

  1. El usuario escribe en la barra de búsqueda del Header.
  2. Con debounce de 300ms, se consulta GET /api/tmdb/search?q=....
  3. Aparece un dropdown con hasta 8 sugerencias.
  4. Al hacer clic en una sugerencia o presionar Enter, navega a /search?q=....
  5. La página SearchResults muestra todos los resultados en grilla.
  6. El usuario puede cambiar entre español e inglés.

3.3 Registrarse e iniciar sesión

Actores: Usuario no autenticado

Flujo:

  1. El usuario navega a /auth.
  2. Selecciona "Crear cuenta" o "Iniciar sesión".
  3. Completa email y contraseña y envía el formulario.
  4. El backend valida las credenciales contra PostgreSQL (Neon).
  5. Si es exitoso, recibe un token JWT que se guarda en localStorage.
  6. El usuario es redirigido al home con sesión iniciada.

3.4 Guardar y gestionar favoritos

Actores: Usuario autenticado

Flujo:

  1. El usuario pasa el mouse sobre un póster y hace clic en "Favoritos".
  2. Se envía POST /api/favorites con el token JWT.
  3. El item se guarda en la base de datos asociado al usuario.
  4. En la página /favorites, el usuario ve todos sus favoritos.
  5. Puede filtrar por tipo (película/serie) y buscar localmente.
  6. Puede eliminar favoritos haciendo clic en el botón nuevamente.

3.5 Ver detalle y tráiler

Actores: Usuario (autenticado o no)

Flujo:

  1. El usuario hace clic en un póster (desde carrusel, favoritos o búsqueda).
  2. Se abre un modal lateral con la información detallada.
  3. El modal carga datos adicionales del backend (GET /api/tmdb/movie/:id).
  4. Si hay tráiler disponible, se muestra un reproductor de YouTube.
  5. El modal se cierra al hacer clic fuera, en la X, o presionar Escape.

6. Esquema de Base de Datos

Prisma ORM genera las tablas automáticamente. El esquema se define en backend/prisma/schema.prisma:

┌─────────────────────┐ ┌──────────────────────────┐ │ User │ │ Favorite │ ├─────────────────────┤ ├──────────────────────────┤ │ id: Int (PK) │◄───────│ id: Int (PK) │ │ email: String (UQ) │ 1:N │ userId: Int (FK) │ │ password: String │ │ tmdbId: Int │ │ createdAt: DateTime │ │ mediaType: String │ └─────────────────────┘ │ title: String │ │ poster: String? │ │ createdAt: DateTime │ └──────────────────────────┘

Un usuario puede tener muchos favoritos. Cada favorito guarda la referencia al contenido de TMDb (tmdbId) junto con metadatos para mostrar sin necesidad de llamar a la API.

7. Instrucciones de Instalación

7.1 Requisitos previos

  • Node.js 16+
  • npm o yarn
  • Una API key de TMDb (gratis en themoviedb.org)
  • Opcional: Base de datos PostgreSQL (Neon o local)

7.2 Backend

# 1. Clonar el repositorio
git clone https://github.com/Maxmoaber/max-tv.git
cd max-tv/backend

# 2. Instalar dependencias
npm install

# 3. Configurar variables de entorno
cp .env.example .env
# Editar .env con tus valores (TMDB_API_KEY, DATABASE_URL, JWT_SECRET)

# 4. Generar cliente Prisma y sincronizar base de datos
npx prisma generate
npx prisma db push

# 5. Iniciar servidor (desarrollo)
npm run dev

# El backend estará disponible en http://localhost:4001

7.3 Frontend

# 1. Ir al directorio del frontend
cd max-tv/frontend

# 2. Instalar dependencias
npm install

# 3. Configurar variables de entorno
cp .env.example .env
# Editar VITE_BACKEND_URL para apuntar al backend
# (local: http://localhost:4001, producción: URL del backend)

# 4. Iniciar servidor de desarrollo
npm run dev

# El frontend estará disponible en http://localhost:5173

9. Despliegue

9.1 Frontend (Netlify)

  1. Conecta el repositorio de GitHub en Netlify.
  2. Configura el build:
    • Base directory: frontend
    • Build command: npm run build
    • Publish directory: dist
  3. Agrega la variable de entorno VITE_BACKEND_URL con la URL del backend en producción.
  4. Netlify deploya automáticamente al hacer push a la rama configurada.

9.2 Backend (Render / Railway)

  1. Conecta el repositorio en Render o Railway.
  2. Configura:
    • Root directory: backend
    • Build command: npm install && npx prisma generate && npx prisma db push
    • Start command: node src/server.js
  3. Agrega las variables de entorno: DATABASE_URL, JWT_SECRET, TMDB_API_KEY.

11. Archivos package.json y package-lock.json

11.1 package.json (backend y frontend)

Cada subproyecto (backend/ y frontend/) tiene su propio package.json. Este archivo es el manifiesto del proyecto para npm:

  • name / version: Identificador del paquete.
  • main: Punto de entrada del servidor (solo backend).
  • scripts: Comandos disponibles — npm run dev inicia el servidor de desarrollo, npm start ejecuta el servidor en producción.
  • dependencies: Paquetes necesarios para que la aplicación funcione en producción (Express, Prisma, React, etc.).
  • devDependencies: Paquetes solo útiles durante el desarrollo (Nodemon, Vite, Tailwind, etc.).
  • private: (frontend) Evita publicar accidentalmente el paquete en npm.

⚠️ package.json se edita manualmente cuando se agrega o quita una dependencia mediante npm install <paquete> — npm lo actualiza automáticamente.

11.2 package-lock.json

NO se edita manualmente. Es generado automáticamente por npm cuando se ejecuta npm install. Su propósito es bloquear las versiones exactas de cada dependencia y sus sub-dependencias, para que todos los desarrolladores (y los servidores de producción) instalen exactamente los mismos paquetes.

  • Contiene el árbol completo de dependencias con versiones exactas, integridad (hashes) y URLs de descarga.
  • Debe incluirse en el repositorio (git) para garantizar builds reproducibles.
  • Si se elimina, npm lo regenera automáticamente en el próximo npm install.

11.3 Diferencia entre dependencies y devDependencies

TipoIncluidas en producciónEjemplos
dependenciesSíexpress, react, axios, bcrypt, prisma/client
devDependenciesNovite, nodemon, tailwindcss, prisma (CLI)

En el backend de Render se ejecuta npm install --production para evitar instalar herramientas de desarrollo, lo que reduce el tamaño del deploy. Por eso prisma (CLI) está en devDependencies pero @prisma/client está en dependencies — el CLI solo se necesita para migraciones, el client se usa en runtime.
